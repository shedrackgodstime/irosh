# PTY Resize & UX Gaps — Analysis and Plan

## Status: Investigated (2026-09-18)

## Root Cause: SIGWINCH Dependency

irosh's resize mechanism is entirely dependent on `SIGWINCH` signals generated by the terminal driver.

### Current flow (`src/sys/unix/pty.rs`)

```
AsyncStdin::new()
  └─ tokio::signal::unix::signal(SignalKind::window_change())  ← registers SIGWINCH handler
  └─ tokio::io::unix::AsyncFd::new(stdin)                      ← wraps stdin for non-blocking reads

AsyncStdin::next_event()
  └─ tokio::select! {
       stdin.readable() → TerminalEvent::Data(bytes)
       sigwinch.recv()  → TerminalEvent::Resize(current_terminal_size())
     }
```

`current_terminal_size()` calls `ioctl(STDOUT_FILENO, TIOCGWINSZ)` to query PTY window size.

### Why resize fails in non-TTY environments

`SIGWINCH` is sent by the kernel **only** when:
1. The process has a **controlling terminal** (session leader with ctty)
2. The PTY master's window size changes (terminal emulator sends resize)

`pexpect`/`script` create PTYs but don't set up a controlling terminal or a terminal emulator. So SIGWINCH is **never** generated. Confirmed empirically: `sigwinch_count = 0` after pexpect spawn + resize.

### What irosh is missing

1. **No PTY window size polling**: irosh only reacts to SIGWINCH. It never queries `TIOCGWINSZ` to detect changes. Even if the PTY size changes externally, irosh doesn't notice.

2. **No fallback resize mechanism**: The `next_event()` loop blocks on `sigwinch.recv()`. If SIGWINCH never fires, no resize events are emitted.

3. **No `TIOCSWINSZ` listener**: When another process calls `ioctl(fd, TIOCSWINSZ, ...)` to change the PTY size, the kernel sends SIGWINCH only if there's a controlling terminal. There's no mechanism to detect the ioctl itself.

### What tmux does differently

`tmux` sets itself as the session leader with a controlling terminal. When the user resizes the terminal, tmux generates SIGWINCH for all child processes. So running irosh inside `tmux` works correctly.

## Fix: PTY Window Size Polling

### Recommended approach: Hybrid polling + SIGWINCH

Add a background resize watcher that:
1. Periodically calls `current_terminal_size()` on the PTY fd
2. Compares with the last known size
3. If changed, emits `TerminalEvent::Resize(new_size)` through the event channel
4. Keeps SIGWINCH as the primary fast path

### Implementation plan

**Phase 1: Add `AsyncStdin::watch_resize()`**
- File: `src/sys/unix/pty.rs`
- Add a `ResizeWatcher` struct that holds:
  - `last_size: PtySize` (from `TIOCGWINSZ`)
  - `interval: Duration` (default 200ms)
  - `sigwinch: tokio::signal::unix::Signal` (existing)
- Method `watch_resize() -> impl Stream<TerminalEvent>`:
  - Uses `tokio::select!` between `sigwinch.recv()` and `tokio::time::interval`
  - On interval tick: calls `current_terminal_size()`, returns `Resize` if changed
  - On sigwinch: returns `Resize(current_terminal_size())`

**Phase 2: Update `AsyncStdin::new()`**
- Add `ResizeWatcher` to `AsyncStdin` struct
- Update `next_event()` to use the watcher

**Phase 3: Handle missing SIGWINCH gracefully**
- If `tokio::signal::unix::signal()` fails (no controlling terminal), fall back to polling-only mode
- If `current_terminal_size()` fails (not a TTY), return initial size from `PtyOptions`

### Key code changes

```rust
// src/sys/unix/pty.rs — new struct
struct ResizeWatcher {
    last_size: PtySize,
    interval: tokio::time::Interval,
    sigwinch: tokio::signal::unix::Signal,
}

impl AsyncStdin {
    // Updated next_event
    pub async fn next_event(&mut self) -> Option<TerminalEvent> {
        tokio::select! {
            // Data path unchanged
            guard_result = self.inner.readable_mut() => { ... }
            // Resize path: hybrid SIGWINCH + polling
            _ = self.resize_watcher.tick() => {
                let size = self.resize_watcher.current_size();
                if size != self.resize_watcher.last_size {
                    self.resize_watcher.last_size = size;
                    return Some(TerminalEvent::Resize(size));
                }
            }
            sig = self.sigwinch.recv() => { ... }
        }
    }
}
```

## UX/Navigation Gaps Identified

### Gaps that made testing harder than necessary

| Gap | Impact | Fix |
|-----|--------|-----|
| `--authorize` opaque failure | No way to debug why trust setup fails | Return fingerprint + reason |
| `trust list` shows "Vault is empty" when `.pub` files exist | Can't verify trust state | `trust list --json` with per-entry status |
| No `irosh discover` | Must know ticket to connect | LAN peer discovery |
| No `irosh inspect <endpoint>` | Can't check peer status | Endpoint inspection command |
| Tickets ephemeral | Must re-copy ticket on every restart | Alias system for peers |
| `--json` and `--log debug` mutually exclusive | Can't script tests with diagnostics | Allow both |
| `check` only checks local | Can't verify connection quality | Connection diagnostics |
| No `irosh status` | Can't see connection state mid-session | Session status command |

### Commands that would help live testing

1. **`irosh discover`** — Find nearby irosh servers on LAN
2. **`irosh peer list`** — Show all saved peers with aliases (already exists, needs `peer list --json`)
3. **`irosh inspect <endpoint-id>`** — Show trust status, connection state, peer metadata
4. **`irosh status`** — Show current session state, connection quality, uptime
5. **`irosh trust list --json`** — Machine-readable trust store with parse status
